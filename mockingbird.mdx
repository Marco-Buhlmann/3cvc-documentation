Mockingbird is a native macOS app. It checks your Mac against an operating doctrine, sets up the controls the doctrine calls for, and tells you when one of them stops working. You can pause or stop enforcement at any time without uninstalling it.

It ships with one doctrine, **Never Touch The Original**. Every rule is a shell probe you can edit, so the score follows whatever rule pack you load.

<Note>
  Mockingbird runs locally. It makes no network calls, and everything it stores is plain JSON on your Mac.
</Note>

## What it does

|  |  |
| --- | --- |
| **Measures** | 58 probes, one for each checkable claim in the doctrine's invariants (N1–N7) and phases (P0–P5). Each one runs live and reports the evidence it found. |
| **Scores** | Weighted by severity: critical 10, high 6, medium 3, low 1. A partial result earns half credit. You get an overall percentage plus a score for each invariant and phase. |
| **Implements** | If a rule has a safe fix, Mockingbird writes it out as a shell script. You read the script, then apply it or run it yourself. Settings are backed up first. |
| **Adjusts** | You can edit every probe, weight and on/off setting in the app, and your changes are saved. You can also add your own rules. |
| **Monitors** | Scans again on a schedule and records regressions, config changes, allow-list changes and movement in T0 stores. |
| **Inventories** | Reads every agent on your Mac — its config, its entitlements, what macOS actually granted it, and what is running right now — and draws what each one can reach. |
| **Accounts** | Rebuilds token use and API-equivalent spend per model, project and week from session files already on your Mac. |
| **Pauses and stops** | The guard reads Mockingbird's state file on every call, so pausing or stopping works right away. |

## Install

Apple silicon, macOS 14 or later.

<Steps>
  <Step title="Download it">
    [mockingbird.marcobuhlmann.com](https://mockingbird.marcobuhlmann.com) — the button on that page serves the current build. The line beneath it reads the version, size and build straight from the published file, so what it says is what you get.
  </Step>
  <Step title="Open the disk image">
    Drag **Mockingbird** onto Applications. It is signed with a Developer ID and notarized, so it opens on a double-click — no trip to System Settings, and no clicking past a warning.
  </Step>
  <Step title="Apply the guard fix">
    Open **Doctrine** and apply the fix beside *The T0 guard hook is installed*. Until you do, Mockingbird measures your Mac but enforces nothing.
  </Step>
</Steps>

<Note>
  If you would rather check the file than trust the page: [`/download/latest.json`](https://mockingbird.marcobuhlmann.com/download/latest.json) carries the version, commit, byte count and SHA-256 of the image being served. `shasum -a 256 Mockingbird.dmg` should match it, and `spctl -a -t open --context context:primary-signature -v Mockingbird.dmg` should answer `source=Notarized Developer ID`.
</Note>

### From source

Requires a Swift toolchain (Xcode 16 or later).

```bash
./scripts/build-app.sh      # release build into dist/Mockingbird.app
./scripts/make-dmg.sh       # and a disk image to hand to somebody
swift build --package-path App   # debug build only
```

`make-dmg.sh` signs the app and the image with a Developer ID, submits them to Apple and staples the ticket, when a certificate is in the keychain; without one it still builds, and says so. The build stamps the repository into the bundle: the commit count as the build number, the short hash as the thing that identifies a build exactly. **Settings** shows both, along with whether the guard hook on disk matches the app that installed it.

### Headless use

You can run Mockingbird from a shell or a cron job:

```bash
# Run every probe and print its evidence
dist/Mockingbird.app/Contents/MacOS/Mockingbird --scan --verbose

# Write every fix script without changing anything
dist/Mockingbird.app/Contents/MacOS/Mockingbird --emit-fixes DIR

# Token use and API-equivalent spend
dist/Mockingbird.app/Contents/MacOS/Mockingbird --ledger --days 90

# Every agent on this Mac, and what it reaches
dist/Mockingbird.app/Contents/MacOS/Mockingbird --roster

# What the guard has blocked, and what each thing does
dist/Mockingbird.app/Contents/MacOS/Mockingbird --explain-blocks
```

```bash
# Where the tokens went that did not need to
dist/Mockingbird.app/Contents/MacOS/Mockingbird --usage --days 30

# Set spending caps from this Mac's own usage, writing nothing
dist/Mockingbird.app/Contents/MacOS/Mockingbird --preset everyday --dry-run

# Which build this is, and the guard and doctrine it carries
dist/Mockingbird.app/Contents/MacOS/Mockingbird --version
```

`--context` prints the allow-listed JSON a copilot may see, `--projection-script` prints the P2 narrowing without installing it, `--price-routine` writes the script that checks public price lists, `--prune-log` strips payloads from older audit entries, and `--restore-pack` resets built-in rules while keeping your custom ones. Run `--help` for the full list.

## Two modes

The same data, twice.

<CardGroup cols={2}>
  <Card title="Nerd Mode" icon="terminal">
    The screens above — probes, evidence, weights, and the full roster matrix.
  </Card>

  <Card title="Intuitive" icon="wand-magic-sparkles">
    Plain language over identical numbers: areas instead of invariants, a card per finding, and the roster map without the matrix.
  </Card>
</CardGroup>

Neither mode is a subset that hides a problem. The mode changes the vocabulary, not the score.

**Settings → Open the app in** decides which one a new window starts in: whichever you used last, or always one of them. The switch at the bottom of the sidebar changes the mode you are in now.

A control that is not holding is titled as the problem in Intuitive mode, not as the goal. "AI agents can't reset your privacy settings" beside a red mark reads as reassurance; "AI agents can reset your privacy settings" reads as what it is.

## Fixes are scripts, deliberately

The doctrine's N3 says an agent's output is only a proposal, and you are the one who applies it. Mockingbird follows the same rule:

<Steps>
  <Step title="Prepare script">
    Writes the change to `~/agent/work/mockingbird/fix-<rule>-<timestamp>.sh` and shows you the whole script.
  </Step>
  <Step title="Apply">
    Runs that same file after you confirm. Nothing is written until you press it.
  </Step>
</Steps>

Fixes are only as aggressive as the doctrine. Removing grants that override the deny list gets rid of blank cheques, including prefixed forms like `sudo`, `timeout 30`, an absolute path or `-c`. It keeps the spelled-out commands that N5 tells you to keep. Moving outbound network access to `ask` leaves narrow `WebFetch(domain:…)` grants alone. No fix deletes anything: removing the guard renames it with a timestamp.

## Enforcement in one paragraph

Settings alone are not a real boundary on a single-user Mac. The one control Mockingbird actually holds is a `PreToolUse` hook at `~/.claude/hooks/t0-guard`. It checks each tool call for T0 paths and destructive commands like `rm -rf`, `DELETE FROM`, `DROP TABLE` and `--force`, no matter which interpreter would run them. It reads the command and the paths the call touches, not the file contents the call carries. Registering the guard adds it alongside your existing hooks. The guard reads `~/.config/mockingbird/enforcement.json` on every call, so pausing works right away and a timed pause ends by itself.

## Storage

Plain JSON, stored locally. Nothing leaves the machine.

```text
~/Library/Application Support/Mockingbird/   rules · scans · events · drills · prefs · T0 baseline
                                             prices.json · ledger cache
~/.config/mockingbird/enforcement.json       read by the guard on every call
~/agent/work/mockingbird/                    prepared fix scripts
```

The ledger reads `~/.claude/projects` and `~/.codex/sessions` and writes nothing back to either. Its cache holds token counts only, keyed by file size and modification time — prices are applied on read, so editing `prices.json` re-prices your history immediately.

The rule pack is written once, on first launch, and Mockingbird never reads it from the app binary again. That way your edits survive upgrades. To pick up new built-in rules after an update, use **Settings → Restore built-in pack**. Your custom rules are kept.

## Limits

<Warning>
  Mockingbird does not isolate anything.
</Warning>

Mockingbird runs as your user. An agent with a general-purpose interpreter can reach anything your user can reach, including this app. What the controls buy you is that a mistake takes more separate steps, and you can see each one. That lowers the risk, but it is not a boundary. For a real boundary, use a second macOS user account that owns `~/agent/`, or a virtual machine.

Mockingbird also can't stop context from leaving your Mac. Anything an agent reads is sent to a model provider. Narrowing the screenpipe projection (P2) is the only control here that affects that, so take it seriously.
